# 基于解析器语法期望和语法作用域构建补全

`pg-parser` 继续作为严格的原始解析树解析器；`pg-completion` 返回补全专用上下文，其中包含强类型语法期望、对象意图、替换范围和尽力而为的查询作用域。解析器在补全点暴露强类型语法期望，但残缺 AST 和 Catalog 对象都不能跨越这条接缝；`pg-completion` 从 Token 流推导作用域，再由调用方拥有的适配器结合元数据解析上下文。该设计沿用已经在 Oracle/MSSQL 中验证过的形态，同时避免使用字符串表示语法规则，并使解析器正确性不依赖编辑器容错逻辑。

## 考虑过的方案

- 不暴露残缺的原始解析树，因为那会迫使每个 AST 使用方理解缺失的必选子节点。
- 不由 `pg-completion` 根据邻近 Token 推断全部语法期望，因为这会在解析器之外复制 PostgreSQL 的语法决策。
- 不在 `pg-parser` 内解析 Catalog 对象，因为解析和元数据具有不同的依赖、失败模式和生命周期。

## 影响

语法产生式必须在收集点显式发布可选 Token 和具名语法槽位。作用域收集刻意采用尽力而为且仅包含语法信息的方式；元数据查询、权限、排序和 LSP 位置转换仍由调用方负责。
